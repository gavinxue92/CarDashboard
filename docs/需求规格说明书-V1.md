## 1. 项目概述

### 1.1 产品定位

面向汽车出口业务的销售团队，把分散在多个工具的客户开发工作收拢到一个工作台内：**沟通（WhatsApp / Telegram）+ 获客（线索发现与管线）+ 业务（报价、合同、素材）+ 账号**。

当前痛点（推断，待销售团队确认）：销售在浏览器、手机、Excel、邮箱之间来回切换，客户对话散落在个人设备上，线索状态和报价进度无法沉淀为团队资产。

### 1.2 场景判定

功能列表中的「样板车展厅」「PI 合同」「成本精算」指向**汽车出口 / 外贸销售**场景：甲方销售向海外买家推介样板车、核算成本并出具形式发票（Proforma Invoice）。

### 1.3 V1 目标

跑通「客户端外壳 + WhatsApp 沟通」的最小可用闭环，验证桌面客户端形态是否被销售团队接受。

**V1 成功的判定标准**：销售在自己电脑上安装客户端，直接进入工作台主界面，点击 WhatsApp 图标，用手机扫码完成绑定，之后可以正常收发消息；应用重启后无需重新扫码。

> **本版范围调整（V1.3）**：去掉工作台账号登录层，本版为**纯本机单机客户端，不部署服务端**。三项目标内决策与全部影响见第 4.3 节。

## 4. V1 范围界定

### 4.1 包含

1. Electron 桌面客户端（Windows 安装包），具备安装、启动、卸载能力
2. 主框架与左侧导航（沟通 / 获客 / 业务 / 账号），**启动直接进入主界面**

#### 5.3.7 双向注入式翻译（V1.4 新增，决策 D7）

**实现约束（前提，不可绕过）**

`web.whatsapp.com` 响应头含 `frame-ancestors 'none'`，只能以 Electron `WebContentsView` 承载。要让译文**长在官方消息气泡内**（本需求的核心形态），**必须在视图上加载 preload 注入脚本**——这是唯一可行路径，**不接受「独立侧栏 / 悬浮面板」等替代形态**（它们做不到"显示在消息下方"）。

注入脚本运行在**隔离世界**（`contextIsolation: true`）：与官方页面共享 DOM，但 JS 作用域互相不可见。因此 **`sandbox` 保持开启，不允许为了注入而关闭沙箱**（内嵌的是第三方远程内容，沙箱是不可退让的安全底线）。

| 编号      | 需求                                                                                                    | 优先级 |
| ------- | ----------------------------------------------------------------------------------------------------- | --- |
| FR-3.22 | 内嵌视图加载注入脚本，在隔离世界中观察消息列表。对官方页面**只做增量监听**（MutationObserver），不轮询、不重写官方 DOM 结构      | 高   |
| FR-3.23 | **入向自动翻译**：识别对方新到达的文本消息，按「对方语言 → 我的语言」翻译，**在原文气泡内、原文下方插入独立的译文节点**             | 高   |
| FR-3.24 | **出向自动翻译**：输入框内容含中日韩字符时，按发送键触发翻译，将译文写入输入框后发送；纯英文/数字/表情内容不翻译，原样发送          | 高   |
| FR-3.25 | 提供**跳过翻译的逃生通道**（**`Alt+Enter`** 强制发送原文），保证使用者任何时候都能原样发送内容。⚠️ **V1.4 实施订正**：原稿写 `Shift+Enter`，但官方页面中 `Shift+Enter` 是**换行**，占用它会剥夺写多行消息的能力，故改为 `Alt+Enter`（官方未占用） | 高   |
| FR-3.26 | ⚠️ **出向翻译失败必须阻断发送**并就地提示，**严禁把原文（中文）发出去**；翻译期间锁定输入框、防重复提交与乱序回填                    | 高   |
| FR-3.27 | **去重与重建**：按文本 hash 缓存译文；消息因虚拟列表回收后重建时，命中缓存直接重新注入，**不重复调用翻译接口**（防重复译文与重复计费）      | 高   |
| FR-3.28 | **范围限制**：只处理**单聊**、只处理**进入会话后新到达**的**纯文本**消息；群聊、图片/语音/文件/贴纸/位置/引用/系统提示一律跳过        | 高   |
| FR-3.29 | 翻译行为严格受设置项控制（`enabled` / `autoReceive` / `autoSend`），弹窗改动**即时生效**，无需重启客户端                      | 高   |
| FR-3.30 | 译文样式受 `fontSize` / `textBgColor` / `textColor` / `personalShow` / `traditionalChinese` 控制，并适配官方明暗主题 | 中   |
| FR-3.31 | 翻译渠道采用**可替换的适配器**：调用方只依赖统一接口。**本版默认实现 = 零注册公共翻译端点**（见第 10 章第 7 项，仅用于验证链路，不用于正式交付）；切换渠道不得改动调用方与弹窗结构 | 中   |
| FR-3.32 | **渠道密钥**：支持构建期内置 + 本机配置文件覆盖（`<userData>/translate-key.json`）；密钥失效时入向静默跳过、出向按 FR-3.26 阻断，**不得导致客户端不可用** | 中   |

**V1.4 本版生效的默认值**

| 设置项                  | 本版默认          | 与契约原值的差异                    |
| -------------------- | ------------- | --------------------------- |
| `enabled`（译者总开关）    | 关，首次进入模块时提示开启 | 契约原值即为关，**待确认**（见第 10 章）     |
| `autoReceive`（接收自动翻译） | 开             | 一致                          |
| `autoSend`（发送自动翻译）   | 开             | 一致                          |
| `peerLanguage`       | 英语（英国）        | 一致                          |
| `myLanguage`         | 中文            | 一致                          |
| `traditionalChinese` | **关（输出简体）**   | ⚠️ **契约原值为开（繁体），本版改默认**      |
| `fontSize`           | 11            | 一致                          |
| `textBgColor` / `textColor` | 默认色      | 一致                          |
| `personalShow`       | 开             | 一致                          |

**仍然休眠、本版不生效的设置项**：`remark`（备注本身另有用途）、`group`、`order`、`channel`、`groupShow`、`groupAuto`、`personalHistory`、`groupHistory`、`recommendReply`、`messageNotify`、`recommendCount`。

**两处实施口径澄清（开发期发现，已按此实现）**

1. **`personalShow` 的语义**：该项与 `groupShow`（群聊显示）同轴，指**单聊里的译文显示开关**，而非「显示我自己消息的译文」。本版把它作为**单聊译文的显示总闸**——关闭后单聊不显示译文，且**不发起翻译**（避免无谓计费）。因 FR-3.28 已整段跳过群聊，`groupShow` 保持休眠。
2. **逃生通道的生效条件**：`enabled` 关闭、或 `autoSend` 关闭、或输入内容不含中日韩字符时，回车**不拦截**，原样发送，无需按 `Alt+Enter`；`Alt+Enter` 只在「本会被拦截」的情形下作为例外出口。出向翻译失败被阻断后，界面提示中会明确告知可用 `Alt+Enter` 直发原文。

> ⚠️ **边界说明**：本功能**实时读取**内嵌页面的消息文本用于翻译，但**不落库、不持久化、不写日志**，除翻译服务商外不发送给任何第三方。消息入库能力仍需 V2.x 通信内核升级（见第 9 节）。

### 5.4 账号归属模型

**一人一机一号**：每个使用者在本机绑定自己名下的 WhatsApp 号码，本机会话相互隔离，互不干扰。

| 编号     | 需求                                                       | 优先级 | 本版处理            |
| ------ | -------------------------------------------------------- | --- | --------------- |
| FR-4.1 | **口径修正**：一台设备绑定并保持一个 WhatsApp 号（原「每个销售账号」的账号维度在本版不存在）   | 高   | 实施              |
| FR-4.2 | 同一台设备切换不同工作台账号时，各账号的 WhatsApp 绑定互不影响                     | 中   | **移出本版**：无账号切换动作，待登录层落地后生效 |

> ⚠️ 会话分区命名必须**参数化**（本版传入固定值，将来传入用户标识）。若本版把分区名写死、后续又沿用同名分区，会出现「任何人登录后都能看到同一个已绑定的号」的串号问题。详见技术方案第 3.2 节。

## 6. 关键技术约束

以下为本阶段已经确认的技术事实与选型结论，直接影响实现，需在开发前达成一致。

### 6.1 硬性约束

| 约束            | 说明                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------- |
| 无法用 iframe 嵌入 | `web.whatsapp.com` 响应头含 `frame-ancestors 'none'`，任何网页都无法以 iframe 方式嵌入。**这是 V1 必须采用桌面客户端形态的直接原因。** |
| 客户端内嵌方式       | 采用 Electron 的 `BrowserView` / `WebContentsView`（或 `webview` 标签）承载官方页面                             |
| 登录态存储         | 使用独立 session 分区（`persist:` 前缀）持久化，实现重启免扫码                                                         |
| 浏览器标识         | 需将 User-Agent 覆盖为常规 Chrome 标识，避免被识别为未知客户端而拒绝加载                                                    |

### 6.2 数据边界

内嵌的官方页面属于第三方域。**V1.4 修订**（原表述「应用无法读取其中的消息内容」已不再成立，因翻译功能需要实时读取）：读取范围严格受限，边界如下：

| 维度           | 结论                                                        |
| ------------ | --------------------------------------------------------- |
| 消息**文本**     | ⚠️ **可读**——但仅用于翻译，仅存在于内存，进程退出即消失                          |
| 消息**存储**     | ❌ 不落库、不写日志、不持久化。系统内不存储任何 WhatsApp 消息                      |
| 派生能力         | ❌ 无法基于消息内容做统计、检索、提醒                                      |
| 历史范围         | ❌ 不补翻历史，只处理进入会话后新到达的消息                                  |
| 消息**出境**     | ⚠️ **会发送至第三方翻译服务商**——这是本版实际产生的跨境数据流，见第 7 章             |
| 富媒体          | ❌ 图片/语音/文件/贴纸/位置等不读取、不上传                                 |

因此「获客管线」「CRM 任务」**仍然不能**建立在 WhatsApp 对话之上——它们依赖的是**持久化、可检索**的消息数据，而本版只做瞬时读取、用完即弃。打通消息数据仍需更换通信内核（见第 9 节 V2.x）。

## 7. 合规与风险

| 风险     | 等级 | 说明与应对                                                               |
| ------ | -- | ------------------------------------------------------------------- |
| 平台条款风险 | 中 → **偏高** | **V1.4 修订**：本版新增注入式翻译，会读取消息 DOM 并改写官方输入框，**已不属于「纯更换浏览器外壳」**（原风险等级以"不注入脚本"为依据）。其中**入向仅插入译文节点，风险增量低**；**出向改写输入框并触发发送，最接近「自动化操作」，风险增量最高**。仍显著低于协议库方案。建议只用于人工一对一沟通，不用于群发、批量添加等行为。 |
| **官方改版失效** | **高** | **V1.4 新增**：注入依赖 WhatsApp Web 的 DOM 结构，官方前端改版（历史频率约 2~4 周一次）即可能导致翻译失效。本版**无服务端、无自动更新**，只能重新发版修复。应对：选择器集中配置化；失配时**静默降级**（不翻译、不报错、不影响聊天）。 |
| 账号归属风险 | 高  | 建议统一使用公司提供的号码，避免销售个人主号被限制后影响业务与人员。                                  |
| **密钥泄露与额度** | 中 | **V1.4 新增**：渠道密钥内置在客户端安装包中，可被提取。应对：服务商侧设**消费上限与告警**；密钥支持本机配置文件覆盖，以便**免发版换 key**（FR-3.32）。 |
| 关联设备上限 | 中  | 一个手机号可关联的设备数量有上限（以官方当前策略为准），需在绑定失败时给出可理解的提示。                        |
| 网络可达性  | 高  | WhatsApp 服务在境外。**部署前需确认销售团队的访问条件与服务器部署位置（境外 / 中国香港等），否则会出现大面积不可用。** 翻译服务的可达性同样受此约束。 |
| 数据合规   | 中 → **高** | **V1.4 修订**：翻译功能会把**客户发来的消息原文**发送至第三方翻译服务商，这是本版**实际存在**的跨境数据流，已不再是「后续模块接入前再确认」的事项。使用前需确认：客户是否知情、服务商所在司法辖区、是否需要脱敏处理。 |
