## 1. 职责边界（先读这一条）

因为 V1 采用「Electron 内嵌官方 WhatsApp Web 页面」方案，本模块必须区分**谁能画什么**：

| 区域                            | 由谁渲染     | 我方能否修改 |
| ----------------------------- | -------- | ------ |
| 关联设备二维码                       | **官方页面** | 不能     |
| 聊天界面（会话列表、消息气泡、输入框）           | **官方页面** | 不能     |
| 扫码过程中的「已扫描待确认 / 正在同步」提示       | **官方页面** | 不能     |
| 工作台标题栏、左侧导航                   | 我方       | 能      |
| 内嵌区右侧功能栏、翻译设置弹窗               | 我方       | 能      |
| 导航内状态点、账号备注、菜单、故障覆盖层、确认弹窗、提示条 | 我方       | 能      |

**结论：本模块的实际交付物是一个「外壳」**，由三层构成：

- **L1 工作台框架**：标题栏、左侧导航、内容区容器
- **L2 模块容器**：加载占位、内嵌区承载、故障覆盖层
- **L3 导航内嵌状态与操作**：状态圆点、账号备注、操作菜单、确认弹窗、提示条

需求文档里 FR-3.5（二维码自动刷新）、FR-3.6（扫码中间态）**由官方页面天然满足**，我方不实现、也无法实现，验收时改为「确认官方页面行为正常」。完整对照见第 10 节。

> **本版前提（V1.4）**：本版为**纯本机单机客户端，无工作台登录层**（需求文档 4.3 已确认）。因此：
> - 客户端启动**直接进入工作台主界面**，本模块不存在「登录后再进入」的前置条件
> - 会话分区标识为固定值（参数化留注入点），隔离由 Windows 用户目录承担
> - 本模块的交互设计**不受此影响**：21 条 WhatsApp 需求中只有 FR-3.10 改了隔离口径，其余 20 条原样实现
>
> 唯一连带变化：因本版**卸载即清除全部数据**（FR-1.7），卸载会连账号备注一起清掉，重装后需重新扫码并重填备注——这一点要写进交付说明，避免被当成故障。

### 1.1 参考产品对齐（V1.1 新增）

用户提供了一张市面同类产品（WhatsApp 聚合工具）的截图作为参照，其结构为：

- 左侧薄栏：自有账号管理（多账号列表、聚合操作如一键已读、分组）
- 主体：官方 WhatsApp Web **全功能原样运行**
- 底部输入框区域：注入式翻译插件（DeepL，把中文译为英语后发送）

**本设计的对齐与差异：**

| 维度    | 参考产品       | 本设计 V1              | 说明                                                                          |
| ----- | ---------- | ------------------- | --------------------------------------------------------------------------- |
| 内嵌方式  | 官方页面全功能    | 相同                  | 对齐                                                                          |
| 外壳厚度  | 左侧一条薄栏     | 相同思路：去顶栏、状态进导航      | 对齐（V1.1 修正）                                                                 |
| 账号数量  | 多账号聚合      | **一人一号**            | 已确认的需求口径，V1 不做聚合                                                            |
| 注入式翻译 | 有（改写官方输入框） | **注入式仍不做（V1.3 修订）** | 注入脚本会抬高封号风险且随官方改版失效。V1.3 修订：新增「翻译设置弹窗」作为接口预留壳（见 5.5 / 7.4），翻译执行能力本身仍在后续版本评估 |

## 5. L2 模块容器

### 5.1 M1 加载中

| 项  | 说明                                                 |
| -- | -------------------------------------------------- |
| 视觉 | 内容区居中显示加载指示器 + 文案「正在打开 WhatsApp…」；同时导航圆点转黄         |
| 触发 | 点击图标后立即呈现                                          |
| 超时 | 10 秒（对应 FR-3.8）；超过 10 秒文案变为「仍在加载，网络可能较慢…」并显示「重试」按钮 |
| 退出 | 页面加载完成或失败                                          |

> 设计意图：V1 的内嵌页面首次加载需拉取较多资源，冷启动偏慢。给反馈比给白屏重要。

### 5.2 M2 / M3 内嵌区

| 项    | 说明                                                                        |
| ---- | ------------------------------------------------------------------------- |
| 尺寸   | **填充内容区全部剩余空间，无我方顶栏**，不滚动、不留白                                             |
| 内容   | 官方 WhatsApp Web 页面，我方不注入任何脚本、不修改 DOM                                      |
| 生命周期 | 切换导航离开时**不销毁**，保持后台运行；返回时直接恢复（已确认：常驻后台，切换回来直接恢复）。代价是常驻期间保持 300~500MB 内存占用 |
| 重载   | 导航 ⋯ 菜单「重新加载」触发 `reload()`，期间圆点转黄                                         |

### 5.3 M4 故障覆盖层

覆盖在内嵌区之上，半透明遮罩 + 居中卡片。

| 场景     | 标题     | 说明文案                              | 主按钮  | 次按钮    |
| ------ | ------ | --------------------------------- | ---- | ------ |
| 页面加载失败 | 页面加载失败 | 无法打开 WhatsApp 页面，请检查网络后重试         | 重新加载 | 查看网络设置 |
| 网络不可达  | 网络连接异常 | 当前网络无法访问 WhatsApp 服务，请联系管理员确认办公网络 | 重试   | —      |

### 5.4 M5 被平台限制

| 项  | 说明                                 |
| -- | ---------------------------------- |
| 触发 | 官方页面呈现账号受限类提示                      |
| 处理 | 我方**无法自动识别**，由「帮助 / 排查指引」承接（见 9.4） |

## 7. 叠加层

### 7.1 O1 解除绑定确认弹窗

```
┌───────────────────────────────────────────┐
│  解除 WhatsApp 绑定                    ✕  │
├───────────────────────────────────────────┤
│  解除后本机将清除登录状态，需要重新用手机   │
│  扫码才能再次使用。                        │
│                                           │
│  聊天记录不受影响，仍保留在手机和官方服务   │
│  器中。                                    │
├───────────────────────────────────────────┤
│                    [取消]  [确认解除]      │
└───────────────────────────────────────────┘
```

| 编号     | 规则                                     |
| ------ | -------------------------------------- |
| IX-3.1 | 弹窗为模态，遮罩阻止背景交互                         |
| IX-3.2 | 默认焦点在「取消」，避免误触回车                       |
| IX-3.3 | 「确认解除」为危险样式（红色）                        |
| IX-3.4 | 确认后立即清除本地分区数据，回到 M1 加载态，官方页面呈现二维码      |
| IX-3.5 | 完成后 Toast 提示「已解除绑定」，导航账号备注行恢复为「点击设置备注」 |

> 文案里必须写明「聊天记录不受影响」。销售最大的顾虑是解绑会不会丢客户对话，不写清楚会不敢点。

## 8. 关键流程详解

### 8.1 首次绑定（销售视角）

| 步骤 | 销售看到                           | 系统行为            |
| -- | ------------------------------ | --------------- |
| 1  | 点击左侧「沟通 → WhatsApp」            | 创建内嵌容器，开始加载官方页面 |
| 2  | 内容区显示「正在打开 WhatsApp…」，导航圆点转黄   | 监听加载完成事件        |
| 3  | 官方页面出现，显示关联设备二维码，圆点转绿          | 我方仅感知「页面已加载」    |

| 7  | 关闭客户端，重新打开                     | 读取本地分区，免扫码直接进入  |

```
检测到页面加载失败 / 渲染进程异常
  → 导航圆点转红，内容区顶部出现 O3 浮条
  → 后台按 5s / 15s / 30s 退避重试
  → 成功：圆点转绿，浮条消失，Toast「连接已恢复」
  → 三次失败：浮条改文案并露出「立即重试」按钮
```

| 编号     | 规则                         |
| ------ | -------------------------- |
| IX-5.1 | 重连过程不打断用户，不弹模态框            |
| IX-5.2 | 重连不影响已保存的登录态，无需重新扫码        |
| IX-5.3 | 重连次数与最后时间写入本地日志，便于排查办公网络问题 |

## 9. 可实现性修正（重要）

以下需求条目在方案 A 下**无法按原描述实现**，需要调整口径或接受替代方案。这是本轮细化暴露出的最大问题。

### 9.1 FR-3.12 连接状态 — 需修改口径

- **原描述**：界面展示当前连接状态：已连接 / 连接中 / 已断开
- **问题**：我方无法获知 WhatsApp 账号的真实在线状态，只能获知内嵌页面是否正常加载
- **修正为**：展示**页面运行状态**（运行中 / 加载中 / 连接异常），语义改为「页面是否正常」，文案避免使用「已连接」这类容易被理解为账号在线的词

### 9.2 FR-3.7 展示登录账号 — 替代方案（已确认采用）

- **原描述**：绑定成功后展示当前登录账号（头像、昵称、手机号）
- **问题**：我方读不到官方页面内的账号信息
- **替代方案**：账号备注。入口在 ⋯ 菜单「设置账号备注」，显示位置在导航 WhatsApp 项下方小字（与参考产品的左侧账号栏位置一致，只是信息靠人工填写）
- **触发方式**：因感知不到绑定成功这个事件，不做自动弹出；未设置备注时账号行显示灰字「点击设置备注」，用户点击即打开输入框
- **存储**：存本机本地（本版无工作台账号维度），与 session 分区关联

### 9.3 FR-3.5 / FR-3.6 二维码刷新与扫码中间态 — 改为验收确认项

- **原描述**：二维码到期自动刷新；状态实时变化：待扫码 → 已扫描待确认 → 已连接
- **结论**：由官方页面天然满足，我方不实现
- **处理**：从「开发任务」移入「验收检查项」，验收时人工确认官方页面行为正常

### 9.4 FR-3.15 被平台限制登录 — V1 不做处理（已确认）

- **原描述**：被平台限制登录时，给出可理解的提示与处理建议
- **问题**：无法自动检测
- **决策**：V1 **不加帮助页、不做自定义提示**。官方页面自身会呈现受限提示，即为销售可见的反馈。优先级降为「低」，「帮助 / 排查指引」页留待后续版本

### 9.5 FR-3.16 手机端解除关联 — 无法感知

- **原描述**：手机端主动解除关联后，客户端能感知并回到绑定引导
- **问题**：无事件可订阅；官方页面自行跳回二维码页，我方无从得知
- **处理**：不做检测。销售看到二维码自然知道要重新扫码。需写入销售使用说明
