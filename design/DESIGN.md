# 海外汽车服务工作台 · 设计说明（v6）

> 本文件只记**布局与已实现范围的现状**，配套可点击原型：`design/prototype.html`（单文件，无依赖，双击即可在浏览器打开）。
> **v6 的驱动是用户两点反馈**：「原型看起来还是自绘的，不是嵌入的 WhatsApp Web」+ 右侧列表栏被删——
> 结论：**HTML 原型永远嵌不了真网页版**（`X-Frame-Options: DENY`），真嵌入只有 Electron 套壳一条路
> → **S0 已开工，真实壳在 `shell/`**（运行：`npm run start -w shell`），原型降级为设计参考稿；
> 同时恢复右侧常驻客户面板（与工具栏并存）+ 列表行注入 CRM 信息（用户拍板「两个都要」）。
> v5 的驱动是用户对拓译截图的逐点反馈；v4 的驱动文档是 `design/SHELL-ROUTE.md`（载体改为 Electron 套壳）；v3 是 `design/CONVERSATION-MODE.md`。
> 凡被后续变更推翻处，本文就地标注——**包括被用户本轮推翻的 v4/v5 结论**。
> 设计目标不是把功能画全，而是**把"继续加功能的接口"设计出来**——后续一个功能一个功能往里填。

## 一、v2 要解决旧版的什么问题

旧版把 18 项功能平铺在左侧导航里，未做的也占位可点，点进去是空的。这不是预留入口，是提前欠债：
用户分不清"哪些能用"，也会把空页面误读成"坏了"。

v2 的取舍只有一条主线：**把"承诺"和"占位"区分开**。

| # | 改动 | 状态 | 解决的问题 |
|---|---|---|---|
| 1 | 导航瘦身 + 灰色「预留（未开放）」区 | 已采纳 | 未做的功能不再伪装成可用入口；灰度本身即诚实 |
| 2 | 账号切换升为顶部全局切换器 | **未采纳** | 保留在左侧导航（按用户决定） |
| 3 | 右栏从「聊天面板」升级为「客户工作区」 | 已采纳 | 对话 / 客户档案 / 成本精算 同屏，不用跳页 |
| 4 | 会话列表项升级 | 已采纳 | 手机号改为「客户名/公司 + 国家 + 意向阶段 + 待跟进时长」 |

> 关于 2：账号的作用域确实是全局的（切换后会话、客户、业务数据全变），放导航里语义偏弱。
> 本次按用户决定保留原位置；若将来账号数变多（矩阵化管理），这一处建议重新评估。

### v3 相对 v2 的变更（原型已改，详见 `CONVERSATION-MODE.md`）

| # | 改动 | 为什么 |
|---|---|---|
| 1 | 消息模型把**方向与语言解耦**（`body{text,lang}` + `translation{text,lang,state}`），主气泡按语言选边 | v2 用 `dir` 猜哪边是原文、硬编码 `zh`/`en` 两字段，违反既定原则「语言对是数据不是代码」 |
| 2 | 补**发送状态**（sending/sent/delivered/read/failed）与**翻译状态**（none/pending/done/failed/skipped） | 后端已是异步翻译 + 先落库原文，UI 必须容得下"翻译中/失败/跳过" |
| 3 | `origin='phone'` 在气泡上显示「手机端 · 未经翻译」 | 手机手打绕过翻译层是已知缺口，必须**显性化**而非无声吞掉 |
| 4 | 消息**逐条操作条**（复制 / 重译 / 引用 / 转发到右栏 / 收藏为话术 / 撤回） | v2 消息节点没有任何操作位 |
| 5 | **发送前常驻译文预览**（译文可就地改、就绪前禁用发送、术语命中可点） | 后端已强制 `draft()`/`send()` 两步，v2 却是静默直发 —— UI 落后于契约 |
| 6 | 右栏改**常驻 + 可展开覆盖层**，与输入区**不再互斥** | v2 切到「客户档案」会把输入区 `display:none`，"看档案就不能发消息"业务上不成立 |
| 7 | 「**24 小时窗口**」三处（筛选 chip / 列表徽章 / 标题行）全部换成「**待跟进**」 | 窗口是**官方 Cloud API 的约束**；走非官方路线后无此限制，该徽章成了误导信息 |
| 8 | 会话列表顶部加**账号筛选器**（含每号连接状态点） | 会话数据早有 `account`，界面完全没有账号维度，无法按号排查"哪个号掉线" |
| 9 | 「**群组**」筛选恢复，并按**会话类型**处理（群头 + 成员数） | v2 移除群组的理由是官方 API 收不到群组；非官方路线下该理由已失效 |
| 10 | 常驻 chip 收敛为 **未读 / 待跟进 / 群组**，其余（阶段/国家/标签）收进「筛选 ▾」 | 不平铺 7 个 chip；同"导航瘦身"原则 |

## 二、布局结构

四栏（v6 起）：**中间整块是官方网页版（含它自己的会话列表），左侧窄账号栏，右侧 = 功能工具栏 + 常驻客户面板**。

│ 64px   │                                                      │ 78px     │ 300px      │
│ (我们的)│  ┌───────────────┬────────────────────────────┐      │ (我们的)  │ (我们的库)  │
│        │  │ 它的会话列表    │ 它的对话区                    │      │ 翻译设置  │ 客户档案    │

│ + 同步  │  │ 列表项=手机号   │ 消息流（气泡一律实际传输文本）： │      │ 客户信息  │ （页签切换， │

│ 设置    │  │               │ 输入框（原生）+ 注入模式行       │      │ 群管理   │            │

**v6 被推翻/修正的既有结论**（就地记录，不粉饰）：

- **v5「客户信息等 CRM 内容走弹层」→ 部分推翻**：客户档案恢复**常驻面板**（与工具栏并存），快捷消息 / 推荐回复仍走弹层。
- **v3 消息模型「主气泡按语言选边」→ 修正为「气泡一律显示实际传输文本」**：方向与语言解耦的数据模型不变（body/translation 分列），
  变的只是呈现——套壳下气泡是网页版画的，我们改不了它，只能在其下方注入译文。
- **「HTML 原型可以代表最终形态」→ 修正**：原型永远是画的；真嵌入只有 Electron 套壳（S0，`shell/`）。

**v5 被推翻的 v3/v4 结论**（就地记录，不粉饰）：

- 「自绘会话列表依然是对的」（SHELL-ROUTE.md §5.4）→ **推翻**：列表交给网页版，我们只在列表项上**注入**标注（v6 起注入 CRM 一行：客户名 · 国家 · 阶段 · 待跟进）；全量数据仍落我们自己的库（观测同步不变），只是不再自己渲染。
- 「右栏常驻是对的，不该照抄弹窗」→ v5 **推翻**（全部走弹层）→ **v6 再修正（用户拍板「两个都要」）**：客户档案恢复常驻面板，与工具栏并存；快捷消息 / 推荐回复仍走弹层。
- 「常驻快捷插入栏是原创资产」→ **降级**：插入能力保留（快捷消息弹层 / 推荐回复 / 引用回复），纪律「插入 ≠ 发送」不变，但不再常驻。

## 三、本次完整实现的功能：客户会话（底座）

这是第一个做完的功能，因为它产出后面所有模块要用的数据。

> ⚠️ **2026-10-13 起，本节「对话区」相关条目已降级为"待按套壳方式实现"**（见 §一 v4 变更表）。
> 它们在原型里仍可交互，但**实现路径变了**：消息渲染、悬浮操作条、双语副行改走**注入（圈一）**；
> 「发送前常驻预览」**被推翻**，改为「拦截发送 + 覆盖层」。
> **v5 再改**：会话列表、右栏、导航也**不再自绘**（见 §一 v5 变更表与 §二）。

**已实现（原型可交互）**

- 左栏账号栏：头像**切号**（每号一块独立网页版的隐喻；断开的号红圈暴露）、添加 / 同步（预留）、所有·未读、设置（预留）
- 网页版列表（模拟原生）：搜索、筛选 chips（所有 / 未读 / 特别关注 / 群组）、列表项显示**手机号/群名** + 摘要 + 原生未读角标
- 注入 **CRM 行**（列表项）：`客户名 · 国家 · 阶段 · 待跟进`（橙色虚线，标明来自我们的库；超 4h 标红）；会话头注入「客户名 · 国家 + 待跟进」
- 网页版对话区（模拟原生）：白/绿气泡、时间与勾、群聊发送者名；**气泡一律显示实际传输文本**（v6：英文原文，我们改不了它的气泡）
- 注入**翻译面板**（入站消息下）：译文行（翻译中/已译/失败可重试/同语种跳过/群聊关）+ **推荐回复**（点开代写成草稿）+ 商务角色（预留）+ 历史翻译按钮
- 注入**模式行**（输入区旁）：`[GPT]将[简体中文] 翻译为 [英语][禁止发送中文][发送确认]`，随「编辑账号」弹窗即时更新
- **编辑账号弹窗**（拓译同款三分栏）：5 个开关真实生效（接收自动翻译 / 群聊自动翻译 / 禁发中文 / 发送确认 / 推荐回复），渠道与语言即时改模式行
- 出站拦截确认层：拦截发送 → 译文可就地改 + 术语可点 + 取消草稿保留；发送确认**关**时演示直发风险、禁发中文仍拦中文
- 消息悬浮操作条（注入）：复制 / 重译 / 引用回复（代写草稿）/ 收藏为话术；出站另有「查看我输入的中文」副行与撤回（留位）
- **右侧常驻客户面板**（v6 回归）：客户档案 / 成本精算页签；客户名/国家/阶段/账号/标签/待跟进 + 结构化字段占位（目的国 / 车型 / 车龄 / 预算）；工具栏「客户信息」可收起
- 预留项点击给出明确反馈：「尚未开放，仅为预留入口」

**刻意没做**

- 真实翻译模型、真实通道消息收发（S1 观测同步进行中，见 `shell/`）
- 译文颜色 / 背景实际生效、多引擎切换与对比、声音克隆（理由见 `CONVERSATION-MODE.md` §五）
- 通话翻译、群发实现、获客相关、PI 合同、样板车展厅

| 会话数据 → 客户维度 | 每个会话挂 `customerId`，天然可聚合（网页版列表只显示手机号，CRM 层在我们库里） | 获客 · 管线与统计 |
| 右栏功能工具栏 | 9 个入口的布局已定（翻译设置 / 代理设置 / 客户信息 / AI问答 / 快捷消息 / 群发 / 群管理 / 工单管理 / 语音输入），未做的点给「预留」反馈 | 业务 · 群发 / 工单；获客 |
| 编辑账号弹窗 | 渠道 / 语言 / 8 个开关的配置形状已定（拓译同款），真实实现接账号配置表 | 全部 · 账号矩阵 |
| 会话数据模型 | 每条消息**原文与译文都保留且分列**（`body` 与 `translation` 各带 `lang`，永不合并） | 全部（可追溯 + 后续抽取） |
| 会话 / 客户字段 | `customerId`（客户可关联多会话）、`accountId`、`type`（direct/group）、`unread` | 业务 · CRM；获客 · 统计 |

**留入口的原则**（按"以后改动的成本"排序）：

1. **数据模型**——成本极高，有了数据就要迁移 → **今天必须留**（上面第一、二、七行）
2. **模块间契约 / 对外接口**——成本中 → 只留对外接口
3. **代码结构与界面导航**——成本低，随时可重构 → **不用预留**

⚠️ 反例：**不要提前搭「插件框架 / 模块系统」**。那是最典型的过度设计，抽象要等真的出现第二个实现时再做。

## 五、已知限制

- 翻译、语言识别、发送状态推进均为**演示模拟**（内置词表 + 定时器），真实实现需接大模型与真实通道
- 「待跟进」当前按"对方最后发言且我方未回"计算，原型里是**预置数值**；阈值（示例 4h 标红）是占位，需真实数据后校准
- 数据是内存中的假数据，刷新即重置；未接任何持久化
- 未接真实 WhatsApp 通道，无签名校验、无幂等、无真实收发
- 「撤回（delete for everyone）」在非官方路线下的可行性**待实测**，原型中先留位
- 原型的"网页版"是**模拟**：列表 / 气泡 / 输入框的样式仿官方网页版；**真嵌入在 `shell/`（S0 已开工）**——
  `<webview>` 加载 web.whatsapp.com 本尊，浏览器里的 HTML 原型因 `X-Frame-Options: DENY` 永远嵌不了真页面
- **套壳路线的固有限制（2026-10-13 新增，详见 `SHELL-ROUTE.md` §二）**：
  - 注入层依赖对方网页版 DOM，**改版即可能失效**，需长期维护选择器；必须配失效自检与**显性告警**（不能静默失败）
  - DOM 观察会**重复看到**同一条消息（滚动 / 重渲染 / 切会话都会重放）→ **幂等是头号风险**，
    必须在落库层真正用上按 `messageId` 去重
  - 每账号约 400–500MB 内存（对照 Baileys 约 50MB）
  - 业务员在**手机**上手打的消息仍绕过翻译层，套壳不改变这一点，只能把 `origin=phone` 显性化
